### 关键洞察

1. **规模不是瓶颈，筛选才是。** 8.5 万条逐条人工不现实，但漏斗把需人工干预的量
   压到 **~300 条**（0.35%）。
2. **两条主线，两个校对模式：**
   - `le_string`：HASH 对齐，**必须有 ENG 源**才能校对，靠左右目录比对。
   - `dict`：key 即英文，**单目录即可校对**，但也失去了原文/译文的物理分离。
3. **零误报比召回更重要。** L1 初版报出 5,478 条「漏译」，核实后**真漏译仅 138**：
   绝大多数是 `RIM_*`（轮毂型号）、`LOGO_*`（电台台标）、`BTN_*`（手柄按键）、
   `exe_hardcoded.txt` 里的动画状态机符号（`clip on` / `aim back` / `exit dive`）——
   这些**本就该保留英文，玩家在游戏里看不到**。
4. **误译有强可检测特征。** 已验证：*源文含操作/导航词 ∧ 译文落身体部位域*。
5. **同词必须分语境，绝不能全局替换。** 三处实证：
   - `SR3 "TAT_REG_BACK": "BACK"` → 「背部」= **误译**（UI 返回键被纹身表污染）
   - `SR4 "WHOLE BACK"` → 「整个背部」= **正确**（躯干纹身）
   - `"Angel, watch your back!"` → 「当心背后」= **正确**（习语）
   三者英文都含 BACK，**只有 key 前缀 + 源文 + 邻近条目能区分**。

## 一、总体架构：五层校对漏斗

```
第 0 层  全量语料 85,410 条
   │
   ├─ L1 机械质检（纯规则，零误报）           ~4,700 条
   │     漏译 / 转换符 / 标签 / 空值 / 乱码 / CRLF
   │
   ├─ L2 一致性冲突（需词表 + 统计）             ~500 条
   │     同源英文多译 / 术语冲突 / 人名地名 / 简繁混用
   │
   ├─ L3 歧义误译（需语境判定，AI 初判）        ~1,200 条
   │     一词多义取错义项（BACK / BUILD / HIT / DASH ...）
   │
   └─ L4 人工定稿                             ~300 条
         专有名词 / 剧情关键句 / UI 短标签
```

**核心原则：越往下越贵，所以要把贵的判定尽量往上推。**
L1/L2 完全可脚本化、幂等、零风险；L3 交 AI 批量初判但**必须带上下文**
（key 前缀 + 源文 + 同文件邻近条目 + 已有译法）；L4 人工终审并**反哺词表**。

## 二、各层设计

### L1 机械质检（`lint_mechanical.py`）

纯规则、只报不改、可反复跑。检查项：

| 检查项 | 规则 | 严重度 |
|---|---|---|
| 漏译 | 译文与源文完全相同且源文含字母 | ERROR |
| 转换符不符 | `%d`/`%s`/`%%`/`%1$s` 多重集与源文不一致 | ERROR |
| 富文本标签错配 | `[format]` `[color:x]` `[/format]` 多重集不一致 | ERROR |
| 换行数不符 | 源文含 `\n` 而译文无（或反之） | WARN |
| 空译文 | 源文非空但译文为空串 | ERROR |
| 残留标记 | 译文含 TODO / FIXME / 英文占位 / `???` | WARN |
| 简繁混用 | CHS 目录检出繁体字 | WARN |
| 行尾一致性 | CRLF 混入 LF 文件 | WARN |
| 键序漂移 | 同一文件键集合与基线不一致 | ERROR |

> **零误报保证**：每条 ERROR 都附 `file:line` + 源文 + 译文，可逐条复核后才应用。

### L2 一致性冲突（`lint_consistency.py`）

建立**全局译法索引**，从 `le_string` + `dict` 两侧汇总 `英文 → {中文译法集合}`。

三类检查：

1. **同源多译**（同一英文原文 → 多个中文）
   实测 SR4 命中 120 组。需分类：
   - `FIGHT CLUB → 搏击俱乐部 / 斗拳俱乐部 / 格斗俱乐部` → **真冲突，需定一个**（该用「搏击俱乐部」）
   - `'Yep.' → 嗯。/ 对。/ 是的。` → **合理差异**（不同角色语气），白名单放行
   - `decal → 贴花 / 贴花 1..10` → **编号后缀**，自动归一，不算冲突

2. **术语表违背**：维护 `glossary.csv`（人名 / 帮派 / 地名 / 武器 / 载具 / UI 通用词），
   译文未命中权威译法即报。**这张表是 L4 人工定稿的沉淀物**，越用越准。

3. **跨库漂移**：SR3 与 SR4 共有文本（`le_data_supplement`）译法不一致的条目。
   两代游戏同源文本本应同译，差异即嫌疑。

### L3 歧义误译（`lint_sense.py` + AI 初判）

这是本方案的核心，也是 `BACK→背部`、`Build→建造` 所属的层。

**检测原理：语义域错配。** 给英文词建**义项表**，标注每个义项的
「所属语义域」与「该域下的正确中文」；再给中文词建**域归属**。
若源文某词取了域 A，而译文落到了域 B，即为错配。

已验证的极简版（高精确率）：

```
源文 key ∈ 操作/导航类词表（BACK BUILD HIT CRAWL CHARGE DASH ...）
  且 译文含 身体部位/器物类词（背部 胸膛 骨骼 引擎 ...）
  →  FLAG: 义项错配
```

**扩展方向**（按游戏域定制）：
- **UI 导航域**：`BACK / EXIT / CANCEL / CLOSE / RETURN` → 返回/退出，禁译 背部
- **建造/成长域**：`BUILD / CRAFT / FORGE / UPGRADE` → 建造/锻造，特定语境下亦可为「成型」
- **战斗域**：`HIT / STRIKE / SLASH` → 命中/劈砍
- **移动域**：`DASH / ROLL / CRAWL / CLIMB / VAULT` → 冲刺/翻滚/匍匐/攀爬

**AI 初判的输入必须是上下文包**，单条裸文本会误判：

```json
{
  "file": "SR3/le_string/static_us.txt",
  "line": 1337,
  "key": "TAT_REG_BACK",
  "key_prefix": "TAT_REG_",
  "source": "BACK",
  "current": "背部",
  "neighbors": ["VCUST_WHEEL_WIDTH_OPTION: WHEEL WIDTH", "STAT_WEAPON_SNIPER: SNIPER"],
  "same_source_elsewhere": ["WHOLE BACK → 整个背部", "ENTIRE BACK → 整个背部"],
  "suspects": ["返回", "背部"]
}
```

带上 `key_prefix` 与 `neighbors` 后，`TAT_REG_BACK` 场景 AI 才能判出
「这是纹身部位表里的残留，实际是 UI 返回键」。

**AI 只输出建议，不直接改文件。** 产出 `review_*.jsonl`，人工/规则确认后由
`apply_fixes.py` 统一回写，并写入 `fix_log.csv` 留痕。

### L4 人工定稿

只处理 L3 标记且 AI 判为「需人工」的条目，预期 ~300 条。
定稿结论**必须回写 `glossary.csv`**，让同类问题下次自动被 L2 拦下。

## 三、执行计划（阶段化）

| 阶段 | 内容 | 产出 | 风险 |
|---|---|---|---|
| **P0** 基线固化 | 全量导出 CSV/JSONL 快照 + MD5；建 `fix_log.csv` | 可回滚基线 | 无（只读） |
| **P1** L1 工具 | `lint_mechanical.py` + 报告 | ~4,700 条问题清单 | 无（只读） |
| **P2** L1 修复 | 转换符/标签/空值等机械修复，人工复核后应用 | 译文修正 | 低 |
| **P3** 词表建设 | `glossary.csv` 骨架 + 从现译法人工提纯高频条目 | 术语权威源 | 无 |
| **P4** L2 工具 | `lint_consistency.py` | ~500 条冲突 | 无（只读） |
| **P5** L2 修复 | 冲突定夺：保留 / 统一 / 白名单 | 译文统一 | 中（需判断） |
| **P6** L3 工具 | 义项表 + 错配规则 + AI 初判管线 | ~1,200 条候选 | 无（只读） |
| **P7** L3 修复 | 逐批复核 AI 建议并应用 | 歧义误译修正 | 中 |
| **P8** 回归验证 | 重跑全层 lint + `verify_release.py` + 重打包 | 零新增 ERROR | 低 |
| **P9** 漏译补齐 | 4,525 条漏译分批补译 | 完整汉化覆盖 | 中（量大） |

### 建议的起步顺序

**先做 P0 → P1 → P2**，理由：

- P0/P1 是纯只读，风险为零，且立刻能拿到真实问题清单来校准后续设计。
- P2 的机械修复（转换符、标签、空值）**零判断成本、零误判**，是确定收益。
- 歧义误译（L3）最复杂也最需要你的判断，放在词表和机械层做扎实之后再上。

## 五、验收标准

一轮校对被认为完成，需同时满足：

1. `lint_mechanical.py` 退出码为 0（零 ERROR）。
2. `lint_consistency.py` 无「真冲突」，仅剩白名单条目。
3. `lint_sense.py` 无未处置 FLAG。
4. `verify_release.py` 通过。
5. `git diff --stat` 中每个 CHS 文件的改动**都能在 `fix_log.csv` 找到对应记录**。
6. 重新打包后游戏内抽样验证（菜单 / HUD / 任务 / 字幕各若干条）。

## 六、风险与已知陷阱

| 风险 | 说明 | 对策 |
|---|---|---|
| **全局替换误伤** | `BACK` 在纹身表是「背部」，在 UI 是「返回」 | 强制按 `key_prefix` + 文件语境判定，禁止裸词全局替换 |
| **语气差异误报** | `Yep.` 的 `嗯。/ 对。/ 是的。` 是合理的角色语气差异 | L2 引入白名单机制，区分「冲突」与「合理差异」 |
| **编号后缀误判** | `decal → 贴花 1..10` 是编号，不是冲突 | 归一化时剥离尾部数字再比对 |
| **转换符误改** | `%%` vs `%`、`%1$s` 位置参数 | 只做集合比对，**绝不自动改写**，人工确认 |
| **简繁串档** | CHT 目录目前为空（仅 .gitkeep），后续派生需保证纯简中 | L1 加「CHS 检出繁体」检查 |
| **回归失控** | 大批量改动后无法定位问题来源 | 强制 `fix_log.csv` 全量留痕 + 分阶段提交 |

### 开发中踩到的三个坑（已在代码注释中标注，勿改回）

1. **型号豁免正则误吞 `BACK`**
   `^[A-Z]{1,4}[\s\-]?\d{0,4}...` 因数字量可为 0，把裸大写单词全当型号。
   改为 `(?=.*\d)` 强制含数字。自检抓到。

2. **`_ONLY_MARKUP` 空白分支位置错误**
   把 `\s*` 写在每个分支**开头**，导致 `{1} {2:...}` 中右花括号后的空格无人消耗，
   整条匹配失败。改为把空白作为**独立分支**。自检抓到。

3. ★ **`apply_fixes.py` 写坏文件（已修复，已由 git 回滚）**
   `_ENTRY_RE` 的 group(1) 是 `"KEY": `（**已含冒号**），我又拼了一个 `': '`，
   产出 `"KEY": : "新值"` 并真的落盘到 3 个文件。
   **已用 `git checkout --` 完整回滚**，并加了三道保险：
   - 拼接改为 `group(1) + 译文 + group(3)`；
   - 写回前重新解析新行，校验 key 未漂移、译文等于目标值；
   - 修复前先在 `.tmp_lint/sandbox/` 副本上验证，并 `diff` 确认只有译文行变化。

   **教训**：任何改 Resource 的脚本，必须先在沙箱副本上跑通 + diff 验证，
   再碰真实文件；且必须有基线 + git 双重兜底。

### ★ 关键方法论：为什么不能「一律重新翻译」

L2 起初报 556 条专名冲突，逐条审后真相是：

- **约 200 条是「两种译法都对，只是没统一」**（`WHEELS`→车轮/轮胎、
  `ZOMBIE`→丧尸/僵尸、`WELL DONE`→干得好/干得漂亮）。
  一律重译 = 把 200+ 条正确译文改掉 = **净损失**。
- **约 127 条是对白**（`...Really?`→`……真的假的？/……真的吗？`），
  是不同角色在不同场景的不同语气，**本就该不同**。
- **真正必须改的只有少数**，且每条都要有客观依据（词频 / 术语表 / 语料实证）。

因此最终采用**词频裁决引擎**（`unify_terms.py`）：
以全库 95,060 条的词频做客观裁判，**3:1 多数 + 绝对频次 ≥3 才自动统一**，
否则一律交人工；语义多义词（`BACK`/`BUILD`/`LEVEL`）由 `DANGEROUS` 表强制拦截。

### 本轮踩的坑（已在代码注释标注）

1. **豁免规则过宽会吞真问题**：`^[A-Z]+$` 类规则把 `BACK`/`SNATCH` 全豁免了。
   修法：凡泛匹配规则必须加约束（`(?=.*[_0-9])`、`(?=.*[^A-Za-z\s])`），
   否则加测试用例卡住（自检已 3 次拦下）。
2. **词频不是语义**：`ASIAN`→亚洲（×26）压过亚裔（×1）、`STREAKING`→天体压过裸奔，
   都是错的。故必须有 `DANGEROUS` 拦截表。
3. **2:1 词频差不足以自动改**：多数是「SR3/SR4 各译一次」，两边都对。
   阈值提到 3:1 + 绝对频次 ≥3。
4. **转换符正则把 `% OFF` 当 `%O`**：18 条误报。修法是先剥离字面百分数
   （`%{1,3}` 后面不跟数字/字母），且 `%` 与字母间**不允许空格**。
5. **标签检查不能对称**：源文 `TAKE [format]…[/format]…[color:teal]…[/format]`
   自身就不平衡（1 开 2 闭），译文修成了 2 开 2 闭。此时报「译文不符」是误报，
   强行「修」会把正确译文改坏。改法：**只在译文是源文真子集时报错**。
