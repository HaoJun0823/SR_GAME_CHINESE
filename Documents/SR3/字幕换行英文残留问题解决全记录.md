# 《黑道圣徒3：重制版》字幕换行英文残留问题解决全记录

> 范围：语音字幕长句在 word-wrap 折行后每行独立查词典导致英文残段残留的完整排查与解决过程
> 涉及版本：v7.2.2 → v7.3（折行重组状态机）→ v7.3.1（空格规范化）→ v7.5.0（Hook J 整串替换）→ v7.5.1（字库容量自适应）→ v7.5.2（探针/dump 清理）
> 日期：2026-09-05
> 关联文档：`3DM-hook重写技术规格.md`（第三方 DLL 注入型汉化方案逆向）、`SRTT3_CN_HANDBOOK.md`、`SRTT3_CN_ACHIEVEMENTS.md`

---

## 1. 问题现象

用户在实测 v7.2.2 时报告：**语音字幕长句出现英文残留**。典型表现为长句英文被引擎按字幕框宽度折成两行显示，其中第一行（或中间行）正常显示中文，而**末尾残段（如 `here.`、`practically`、`worries`、`walker`）原样显示英文**。

关键事实：

- 引擎在调用 hook 之前，会按字幕框宽度对长句执行 **word-wrap（`sub_14085A1F0` 折行布局）**，把长句拆成多行，**每行独立查词典**；
- 拆出的残段（如 `here.`）并非完整句子，在词典中必然 miss → 原样显示英文；
- 因此这**不是截断 bug**，而是 **折行机制 + 逐行查词典** 的固有行为。

---

## 2. 根因定位（证据链）

### 2.1 引擎折行机制确认

- 引擎在调 hook 前按字幕框宽度把长句拆成两行（示例：第 569 行 78 字符 + 570 行 `here.`）；
- 每行独立查词典 miss → 原样显示英文。

### 2.2 词典形态佐证

- 游侠（某第三方资源替换型汉化包）`ali213.d12` 词典 17411 条 **KEY 全为英文整句**（UTF-16），无任何折行残段 → 证明其 hook 在折行前；
- 自研 v7 词典 `voice_005.txt:197`、`voice_009.txt:622/774` 等**完整句译文早已存在**，只是被折行残段绕过了查表；
- 3DM btxt 排查（全程只读，仅 `.temp` 落分析脚本）：本地无 3DM 原版词典（`3DMGAME` 目录仅 `3dm.ttf`+`3dm.dds`，`text.btxt` 缺失），`.temp\text.btxt` 系自研 `build_btxt.py` 重建件（5220 条）非原件；用户引用的三组折行残句实抓于 `scripts\DumpText.dtxt` 210–221 行（引擎折行后残段）——**3DM 架构同样存在长句漏翻**（其查找 = CRC32 整串精确匹配 + 一次 trim 重查，无拼接、无部分匹配、无状态机）。

**结论**：长句折行残段漏翻是引擎 word-wrap 机制导致的通用问题，必须**在折行前整串替换**才能根治。

---

## 3. 第一轮尝试：v7.3 折行重组状态机（失败）

### 3.1 方案设计

在折行后残段层面做“拼接重查”：

- 缓存 miss 残段；
- 拼接残段形成整句重查词典；
- 命中后按比例切分译文回填各行。

三态状态机：

| 状态 | 行为 |
|------|------|
| IDLE | 学习段1（缓存第一残段） |
| LEARN | 缓存段1，等段2拼接 |
| STABLE | 按比例切分译文 |

### 3.2 部署与验证

- v7.3 完成部署（commit `d76baea`）：修复 STABLE 缺拼接尝试、LEARN 遇噪音误重置两缺陷，10 场景模拟全通过，Release x64 零警告零错误；
- v7.3.1 空格规范化层（commit `f88eba9`）：根因为词典 KEY 含双空格而引擎文本始终单空格规范化，1917/9630 条 KEY 含连续空格（约 1/5）；方案：加载时存原键+规范化键+trim 键+trim 规范化键，运行时 LookupNode 三级重查（整句→trim→规范化），WrapTryConcat 变体 3 拼接结果规范化重查，验证 12 场景全通过。

### 3.3 实测反馈（仍失败）

用户测试三句话换行字幕**仍未翻译**：

- 日志显示 `wrap=1`（仅 1 次命中）；
- dump 中残段仍在；
- 引擎本次 dump 文本保留双空格（与 v7.2 时代单空格推断矛盾）；
- 折行状态机 + 规范化重查在**多残段场景**下行为仍不可靠。

**结论：v7.3 折行重组状态机路线废弃。** 状态机依赖逐行到达顺序与上下文拼接，多残段、噪音、行序抖动时不可靠，且需要对模板内容做风险较大的改动。

## 4. 第三方方案调研（折行前替换的可行性证据）

### 4.1 游侠式方案调研

- `ali213` 附带包为 Volition cond v6 vpp_pc 格式，基于旧版基础重打包（缺 ps5/xbs 文件），改动 129 文件，字体暴增 9–10 倍（`font_body_nobdr.gvbm_pc` 2MB→22MB，塞中文字形图集）；
- `subtitle_us.le_strings` 每条英文整体替换为高位槽码字符（`Հ` `э` `Ǩ`…），条目 1:1 对齐——即槽码方案。

### 4.2 游侠 DLL 词典逆向

- `ali213.d12` 词典解密成功：17411 条（XOR→zlib→XOR），KEY=英文整句 UTF-16，VAL=槽码中文 UTF-16；
- **三句台词全部以完整句收录、无折行残段** → 游侠 hook 在折行前。

### 4.3 游侠 SIG3 特征码 → Hook 点定位

- 游侠三处 hook：
  - **SIG1**：字体 GPU 内存池 32MB→64MB（与文本折行无关）；
  - **SIG2**：`sub_140418B30` 图像/UI 文字绘制包装；
  - **SIG3**：命中 `sub_1402D2BC0` **字幕绘制函数**，折行在此函数内部（`sub_14085A1F0` 折行布局）发生 → 游侠在入口 hook 整串替换后引擎对中文自然折行；
- trampoline stub 模板使回调 rcx = 函数第一参数 = 字符串指针；对字幕函数直接整串替换比游侠更正确（游侠按对象布局猜偏移 +96/+104）。

**结论：Hook J（游侠 SIG3 路线）可行** —— hook `sub_1402D2BC0` 字幕绘制入口（折行前整串替换），词典 KEY=英文整句直接兼容；相比 v7.3 状态机更简单。

## 5. 字幕冻结问题的二次排查（v7.5 前）

- 用户实测 v7.5 时遇到字幕冻结，排查过程：
  - IDA 重启（清理僵尸进程释放锁）；
  - RefreshText 门控机制修正为 vtable+0x40 虚调用（非脏位）；
  - 0x1436782D8 确认为 .pdata 异常表误读，真虚表基址=0x140E4B168（vint_element_text），slot8(+0x40)=0x14082D9A0；
  - slot8=0x14082DC70 仅 4 条指令读+0x14C bit1（脏位），门控 = 脏位非独立机制；
  - sub_14082DF80 置脏仅在 UI 初始化事件（sub_14041A880）发生非每帧；
  - **根因：UI 重建→置脏→首帧 Format 清脏后 bit1 恒 0→门控恒假→英文布局句柄 a1[40] 每帧重放→冻结**；
  - 修复思路：让 STABLE 期间目标对象每帧重新变脏。

（此问题在 v7.5.0 Hook J 完整实现后不复现——Hook J 不依赖状态机与每帧重放。）

## 6. 最终方案：v7.5 Hook J 整串替换

### 6.1 设计

- **Hook 点**：`sub_1402D2BC0` 字幕绘制入口（16 字节特征码），签名：`double __fastcall(wchar_t* text, float a2, double a3, int a4)`；
- **detour 逻辑**：
  1. 剥离 `\n<ms>` 时长码；
  2. 整串查词典；
  3. 命中 → 回填尾码；
  4. 调原函数（引擎对中文自然折行）。

### 6.2 开发踩坑

- **尾码重复追加 bug**：有尾码时按主体查询+回填，无尾码时整串查；修复尾码重复追加逻辑；
- 编译零警告零错误（569344B）；
- README 更新 + ini 配置 `subtitle_early`（默认 1）。

### 6.3 交付

- **v7.5.0**（commit `49a31b5`）：部署 `SR3R_I18N.asi` + ini `subtitle_early=1`；
- 实测通过：字幕长句整句替换、折行正确。

## 9. 关键结论与经验

1. **root cause 是引擎 word-wrap 折行 + 逐行独立查词典**，不是词典缺词，也不是截断 bug；
2. **任何“折行后处理”路线（状态机、拼接重查）都不可靠**——依赖行序与上下文，多残段/噪音行时行为无法保证；
3. **唯一正确解是“折行前整串替换”**：hook 字幕绘制函数入口，剥离时长码后整串查词典，命中回填后交给引擎自然折行；
4. **第三方资源替换型词典 KEY 为英文整句**，是验证“折行前替换”可行性的强证据；
5. 词典 KEY 空格规范化是**必须处理的数据层问题**（约 1/5 条目含双空格）；
6. 排查 UI 冻结类问题时，需要以数值实证（IDA 单步 + 脏位跟踪）确认门控机制，不能靠猜测；
7. 归档分析材料涉及第三方汉化时须做品牌脱敏（侵权风险），策略 = 泛化措辞。
